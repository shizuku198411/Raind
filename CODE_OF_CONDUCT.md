# Code of Conduct

Raind is intended to be a respectful and collaborative open-source project.

## Expected behavior

Project participants are expected to:

- be respectful and constructive
- assume good intent where reasonable
- focus criticism on ideas, code, documentation, and behavior rather than people
- be patient with new contributors and users
- communicate clearly when discussing security-sensitive or host-affecting changes
- respect maintainers' time and review capacity

## Unacceptable behavior

The following behavior is not acceptable:

- harassment, threats, personal attacks, or discriminatory language
- repeated disruptive comments that derail technical discussion
- intentionally misleading bug reports or security claims
- publishing private security vulnerability details before coordinated disclosure
- sharing private information without permission
- hostile behavior toward users, contributors, or maintainers

## Security discussions

Raind includes security-sensitive container runtime code. Please do not publicly disclose suspected vulnerabilities in issues, pull requests, or discussions.

Use GitHub Private Vulnerability Reporting from the repository's **Security** tab. See [`SECURITY.md`](SECURITY.md).

## Enforcement

Maintainers may take reasonable action to protect the project and its participants, including:

- asking for clarification or a change in tone
- editing or hiding comments when supported by the platform
- closing or locking issues or pull requests
- blocking users from the repository when necessary

Enforcement decisions should be proportional to the behavior and the impact on the project.

## Reporting conduct concerns

For non-security conduct concerns, please contact the project maintainer through GitHub. If the concern involves a security vulnerability, use GitHub Private Vulnerability Reporting instead.
